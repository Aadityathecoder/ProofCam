# Local development

## Python environment

The combined benchmark and provenance environment requires Python 3.12+ because of the pinned NumPy and SciPy releases. The macOS system Python 3.9 cannot install these versions. Keep the system interpreter unchanged and use a virtual environment:

```sh
bash tools/setup-python.sh
source .venv/bin/activate
python -m unittest discover -s benchmark/tests -v
python -m unittest discover -s provenance/tests -v
```

The setup script finds a compatible interpreter on PATH, installs both existing requirements files into the ignored `.venv`, and checks dependency consistency. To choose an interpreter explicitly, set `PROOFCAM_PYTHON=/path/to/python3.14` when invoking the script. The script preserves an existing environment and reports an incompatible one rather than deleting it.

Tests use temporary fixtures; downloaded corpus media is not needed for these two unit suites. Full benchmark runs and the three-source parity fixture generator still require the documented corpus.

## Swift package builds

The macOS Command Line Tools can build the core library and parity executable:

```sh
swift build --package-path ios-benchmark/Core -c debug
swift build --package-path ios-benchmark/Core -c release
```

Complex DCT basis and RGB packing expressions have been split into typed intermediate values to avoid Swift compiler type-checking timeouts. The arithmetic and channel layout are preserved.

## XCTest and iPhone app validation

Full Xcode is required on this Mac for XCTest and the iOS simulator SDK. The Command Line Tools installation alone reports `no such module 'XCTest'`. After installing Xcode, open it to complete its initial setup. If its developer directory is not selected, use a per-command override:

```sh
DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer bash ios-benchmark/tools/validate-mac.sh
```

That script runs Debug and Release Swift tests followed by an unsigned Release simulator SDK build for the host architecture. It builds the app target directly, so compilation does not require an installed simulator runtime. Launching the app in Simulator still requires a runtime. Signing and physical iPhone validation are separate steps described in the [iPhone instructions](../ios-benchmark/README.md).
